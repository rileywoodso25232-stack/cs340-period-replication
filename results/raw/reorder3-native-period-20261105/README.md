# reorder_3：PERIOD 与 Native 自定义对照

## 执行信息
- 成员：1240014957 吴明阳
- 日期：2026-11-05
- 环境：period-cs340 Docker 容器，WSL2 Linux。
- 用例：reorder_3，默认参数为 2 个写线程、1 个检查线程。
- Native：Clang 10.0.0，使用 -g -O0 编译，未进行 PERIOD 插桩。
- PERIOD：使用容器中已有的插桩二进制，本次未重新构建。
- 两种程序均不传入额外命令行参数。

## 方法
- Native：3 组，每组最多 1000 次执行，单次超时 5 秒，组时限 120 秒。
- PERIOD：3 组，深度 3，运行预算 1000，子进程超时 5 秒，外层超时 120 秒。
- Native 判定依据：输出同时包含 Bug found! 和 Assertion。
- PERIOD 判定依据：搜索日志中的断言失败诊断及保存的失败调度。
- 每组使用独立输出目录，保留全部运行记录。

## 结果

| Native | 1 | 1000 次执行 | 0 | 0 |
| Native | 2 | 1000 次执行 | 0 | 0 |
| Native | 3 | 1000 次执行 | 0 | 0 |
| PERIOD | 1 | 27 个受控调度 | 6 个失败调度 | 0 |
| PERIOD | 2 | 27 个受控调度 | 6 个失败调度 | 0 |
| PERIOD | 3 | 27 个受控调度 | 6 个失败调度 | 0 |

Native 三组均无其他运行错误。
PERIOD 三组驱动退出码均为 0；驱动退出码不代表目标程序无缺陷。
6 个失败调度不代表 6 个不同缺陷。

## 结论与限制
在当前用例和配置下，PERIOD 三组均检出断言失败；
Native 在每组 1000 次执行中均未检出。
未检出不能证明程序没有缺陷。

这是自定义 Native 对照，不是论文中 PCT、Random 等基线的复现。
原生执行次数与受控调度数含义不同，不视为等价搜索工作量。
双方计时范围不同，不直接比较耗时或计算加速比。
PERIOD 使用已有二进制，完整构建设置尚未重新核验。
本次仅覆盖一个用例，结果不能推广到其他程序。
