# reorder_3：共享内存兼容修复后的 Serial / PERIOD 候选驱动对照

日期：2026-11-05。执行环境：period-cs340 Docker 容器，WSL2 Linux。
本记录用于单用例预实验与驱动兼容性验证，论文 Serial 基线对应关系尚待进一步核实。

## 修复与方法

旧串行驱动首次运行出现退出码 139。排查发现 Python 驱动与已构建目标的共享内存布局不一致。
从归档目标二进制 DWARF 调试信息核实：线程容量 100，数组容量 3964，数组元素 uint16；
Sched_Info 大小为 24008 字节，四个数组的偏移分别为 20、220、8148、16076。

目标 SHA256：`ed2d13809b87a00eaaba76ac0f1faf4871a489a0960993e5963dc89b4bb13db9`。
双方使用同一目标二进制与配置。独立副本修复 IPC 布局、增加附着错误与容量检查；
Serial 保留 run_OldPDS.py 的 SBPSched 搜索控制流，PERIOD 保留 run_PDS.py 的 SBPMESched 控制流。
原始驱动、此前失败记录及旧实验材料均保留。

双方各三轮，按 Serial / PERIOD 交替、逐轮串行执行：

- 深度参数均为 `-d 3`，运行预算 `-f 10000`，子进程超时 `-t 5`，外层超时 120 秒。
- 实际周期范围不同：Serial 为 3/4/5，PERIOD 为 2/3/4。相同深度参数不表示相同周期范围。
- 各轮使用独立目录。参数、二进制哈希和适用范围见 [manifest.json](manifest.json)。

失败调度数量不等于不同缺陷数量；双方均触发 reorder_3 的同一处预期断言。

## 失败重放

本轮各取第一组的第一条保存失败调度，在独立目录重放。

| 方法 | 保存的失败调度 | 重放驱动退出码 | 重放目标退出码 | 断言重现 |
|---|---|---:|---:|---|
| Serial | serial/group-1/out_reorder_3_bad_1/Errors/000001_0000010_assertion-failed | 0 | -6 | 是 |
| PERIOD | period/group-1/out_reorder_3_bad_1/Errors/000001_0000006_assertion-failed | 0 | -6 | 是 |

双方均输出 `Bug found!`，随后在 `reorder_bad.c:80` 的 `checkThread` 中触发 `Assertion '0' failed`。
目标退出码 -6 表示 SIGABRT。重放驱动没有传递目标状态，故驱动退出码 0 不表示目标正常完成。
重放包装器单独记录目标退出码；命令、原始日志、目标状态与结果 JSON 见
[重放证据](replays-0ff8_nxa/)。

## 结论与限制

在当前二进制、用例与参数下，两种兼容候选驱动均连续三轮检出断言失败，且首轮保存的失败调度可以重放。
此结果支持本轮驱动入口与证据链验证，不代表完整论文复现。

双方除调度策略外，仍保留上游不同的运行时放大及初始化逻辑；计时仅作描述性记录，不计算加速比。
尚未覆盖多用例、完整硬件与软件环境冻结、其他基线及论文整体结果对比。
此前使用 1990 数组容量的结果保留为历史预实验，不与本轮数据混合统计。

完整本地备份保留可执行程序；整理 Git 提交时应排除二进制与构建产物，保留其哈希、日志、配置、补丁及失败调度。
仓库默认忽略 out_* 目录，入库时须确认失败调度确实被纳入提交。
