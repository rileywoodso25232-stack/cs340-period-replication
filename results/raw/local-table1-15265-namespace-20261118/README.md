# CVE-2017-15265 搜索/重放命名空间对照（2026-11-18）

目的：只改变“重放是否与搜索处于同一个 IPC 命名空间/状态”这一个因素，检查正式批次中
“搜索记录了失败、但重放不复现”是否是搜索/重放状态隔离造成的。

## 方法

每次试验：

1. 用 PERIOD 驱动跑一次完整搜索（深度 5、预算 10000）；
2. 取本次搜索的第一条失败调度，在**同一个 `unshare --ipc` 命名空间内**（搜索之后）
   立即重放一次；
3. 把同一份失败调度复制到新目录，在**独立的新 IPC 命名空间**里再重放一次。

驱动、目标、深度、预算、超时、机器均相同；唯一差异是重放所在的命名空间/状态。
共 5 次试验。

## 结果

| 试验 | 搜索 | 同命名空间重放 | 新命名空间重放 |
|---:|---|---|---|
| 1 | 完成 96/1/11 | dry-run ASan 中止 | confirmed（-6） |
| 2 | 完成 96/1/11 | confirmed（-6） | confirmed（-6） |
| 3 | 完成 96/1/11 | confirmed（-6） | confirmed（-6） |
| 4 | dry-run ASan 中止 | 未运行 | 未运行 |
| 5 | 完成 96/1/11 | confirmed（-6） | confirmed（-6） |

可比较 4 次：同命名空间确认 **3/4**，新命名空间确认 **4/4**；同命名空间的一次失败是
重放前 dry run 又被 UAF 打断，而不是“状态使它更容易复现”。

## 解释与边界

- **不支持**“搜索/重放命名空间状态隔离导致不可复现”的假设：新命名空间没有更差，反而 4/4 确认。
- 正常搜索产生的失败调度在两种命名空间里都能复现；正式批次中那次早触发更像是**目标时序造成的
  假阳性记录**，而不是重放状态丢失。
- 试验 1 的同命名空间重放 dry-run 中止，再次说明 dry-run 阶段的中止与命名空间无关。
- n=4 可比较试验，结论是“不支持该假设”，不是“证明所有失败都因果可靠”。
